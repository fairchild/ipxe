Diskless display architecture

A picture,bootstrapped.

How a bare machine becomes a private picture frame: trusted network boot, a single-use role acknowledgement, authenticated media fetched directly from its source, and pixels written without a browser or local disk.

01 / The idea

The frame owns no library.

The frame is a RAM-only role for a netbooted machine. It receives just enough configuration to authenticate to a separate photo service, prefetches the selected images into memory, and paints the current image to every available display sink.

Important distinction. iPXE carries boot intent and delivers configuration. It does not proxy, copy, publish, or host the private photographs.
P—01

Diskless by design

The operating system, role configuration, image cache, and rendered preview all disappear at power-off.

P—02

Source stays authoritative

An operator changes the curated set at the photo service. The frame learns the new set on its next manifest poll.

P—03

No browser ceremony

No cookies, login redirects, or JavaScript application. One bearer credential authenticates JSON and image requests.

02 / The system

Three planes. One narrow handoff.

Keeping boot, control, and media responsibilities separate is the core architectural move. The only cross-plane payload is the role config: a manifest URL and its source-scoped bearer token.

03 / The flow

From cold metal to live pixels.

  1. Firmware finds iPXE Boot

    The site’s ordinary DHCP server still assigns the network address. The bootstrap container answers only the PXE questions, selects an architecture-specific binary, and serves it over TFTP.

  2. iPXE establishes transport trust Boot

    The custom binary synchronizes time, then chains to the boot service over HTTPS using root-certificate fingerprints compiled into the binary. The control plane returns the diskless Alpine kernel, initramfs, and boot parameters appropriate to the machine.

  3. The assigned role selects the path Control

    A machine assigned the frame RAM role receives role=frame, a non-secret machine identifier, and a fresh single-use role_nonce on its kernel command line. Unlike an install role, this path never partitions or writes local storage.

  4. Userspace acknowledges this boot Control

    The discovery overlay posts the nonce to role-ack. A valid, unconsumed nonce marks the machine active and returns the operator-staged role config. The config is written to a mode-0600 file in tmpfs; the raw HTTP response is private while parsed and is then removed.

  5. The frame pulls from the source Media

    frame-display supervises the renderer. The renderer reads the manifest URL and source token, sends the token as an Authorization: Bearer header, then repeats that header for every asset URL returned by the manifest.

  6. Showable assets are held in RAM Media

    Asset URLs are resolved against the manifest URL. Optional SHA-256 values are checked before an image becomes showable. If a manifest poll fails, the previous in-memory set remains available; an individual asset that fails to fetch or verify is not displayed.

  7. Composition is separate from output Display

    Each image is resized to fit and letterboxed—never guessed-cropped— for each sink. The HDMI framebuffer is written directly without X; a preview PNG provides a hardware-free diagnostic surface; when its optional runtime library is present, the e-ink sink refreshes only when the image changes.

  8. Telemetry observes; it does not serve media Operations

    Boot beacons identify milestones. Heartbeats report what the node is doing now. Out-of-band recovery is deliberately separate from the rendering and photo-authentication paths—and must use RAM-role-aware health rather than the age of the last boot acknowledgement.

04 / Media contract

Two authenticated reads.

The frame source contract is intentionally smaller than a gallery API. A manifest names the current set; each listed URL returns bytes when called with the same bearer header.

Required behavior

  • Return JSON, not an HTML login or redirect.
  • Reject missing or invalid authorization.
  • Resolve relative asset URLs against the manifest URL.
  • Keep the source and every returned asset URL on trusted HTTPS origins.
  • Include SHA-256 when possible so truncated or altered fetches are rejected.
# 1. Read the curated set
GET https://photos.example/device/manifest
Authorization: Bearer <source-token>

200 application/json
{
  "images": [
    {
      "name": "mountain-dawn.jpg",
      "url": "./assets/mountain-dawn.jpg",
      "sha256": "<64 hex characters>"
    }
  ]
}

# 2. Read each image with the same header
GET https://photos.example/device/assets/mountain-dawn.jpg
Authorization: Bearer <source-token>

200 image/jpeg
<image bytes>

05 / Trust boundaries

Private photos. Explicit assumptions.

“RAM-only” describes the node, not the entire system. The control plane must persist the role config so a future boot can receive it. Clear language about where data lives is part of the security design.

Public by design

Code and boot artifacts

Repository contents, compiled bootstrap binaries, and the Alpine overlay may be publicly downloadable. They must contain no private keys, bearer tokens, LAN inventory, or operator-specific addresses.

Persistent + protected

Operator and control plane

The source token lives in an operator secret store and in the control plane’s dashboard-protected role_config record. It is configuration data, not source code, and is cleared with the role.

Ephemeral

Booted frame node

The role nonce is single-use. The delivered config is mode 0600 in tmpfs. Images, composed canvases, and previews remain in RAM and die with the boot. The source token is not placed in a URL or process environment.

Trust assumption

Managed network + trusted source

This is not remote attestation. Early initramfs fetches include a plain-HTTP overlay because RTC-less hardware cannot validate TLS at that stage. The current design therefore assumes a managed LAN.

Server identity

Custom iPXE validates the HTTPS boot service against certificate fingerprints compiled into the binary after an NTP clock sync.

Boot activation

A fresh, machine-bound, single-use nonce proves that a RAM-role boot reached userspace. It is not a reusable machine credential.

Operator control

Role assignment and role-config writes require dashboard authorization. The boot node cannot use its role nonce to rewrite its own configuration.

Photo access

The frame source decides what the bearer token may read. Both manifest and assets must fail closed without that token.

Content integrity

Optional per-image SHA-256 detects a bad or truncated asset fetch. It does not replace TLS or source authorization.

Do not widen the credential boundary

The renderer sends the bearer token to every asset URL in the authenticated manifest, including absolute URLs. Configure an HTTPS source you trust to return same-origin—or deliberately trusted—asset URLs. Never put the token in a query string, kernel command line, image name, log message, repository file, or public overlay.

06 / Operations

Change the source, not the frame.

Curation happens at the photo service. Credential delivery happens at boot. Rendering continues from RAM when the network has a bad afternoon.

Operator intent Change here When the frame sees it
Add, remove, or reorder photographs The curated set at the frame source Next successful manifest poll
Rotate the source bearer token Source grant and control-plane role_config Next reboot and role acknowledgement
Change the manifest endpoint Control-plane role_config.source Next reboot
Update renderer or boot behavior Build and publish a fresh Alpine overlay Next netboot; verify artifact hashes
Recover a healthy, reachable node Prefer a soft reboot over outlet power Immediately; re-runs the complete netboot path
Recover an unreachable node A RAM-role-aware out-of-band policy, with bounded retries Only after health semantics identify a real stall

Deploy order is a wire contract

When node telemetry or boot parameters change, deploy the compatible control plane first. Then rebuild the overlay from the same reviewed source, publish it, compare local and remote hashes, and boot a node. Green tests in separate repositories do not prove the cross-repo wire.

Do not arm the current age-based watchdog against a frame

A healthy frame acknowledges once per boot, then sends heartbeat events without refreshing the machine row’s boot timestamp. A probe based only on that timestamp eventually calls a healthy frame stale. Use the boot feed or a RAM-role-aware stall verdict before enabling automatic power.

07 / Glossary

Words we use on purpose.

These terms keep conversations precise across firmware, control-plane, photo-service, and display work. Search by term or concept.

20 terms
Bootstrap
The site-local proxy DHCP and TFTP service that gives firmware the correct iPXE binary without replacing the site’s normal DHCP server.Say: bootstrap container
Control plane
The service that owns machine records, role assignment, boot-script rendering, nonces, role configuration, and operational telemetry.Not: the photo host
Data plane / media plane
The direct authenticated path from the frame node to the photo service. Private images do not pass through iPXE.Say: direct source fetch
Machine / node
A physical or virtual computer known to the control plane. “Frame” names its assigned role, not its identity.Node = running machine
Discovery OS
The small Alpine environment netbooted into RAM. It inventories, registers, acknowledges RAM-role boots, reports health, and starts role services.Diskless userspace
apkovl / overlay
A gzipped filesystem overlay applied by Alpine’s initramfs before OpenRC starts. It carries the discovery and frame scripts, never runtime secrets.Artifact, not image library
Role
Operator intent attached to a discovered machine. A role selects either a disk-install path or a RAM-only runtime path.Role = desired first behavior
RAM role
A role that boots the diskless overlay with a role name on the kernel command line and writes nothing to local storage.Frame is a RAM role
Assignment
The dashboard-authorized transition that binds a known machine to a role after architecture and lifecycle checks pass.Assign once; boot repeatedly
Role nonce
A random, machine-bound, single-use value minted for one RAM-role boot. It proves that boot reached userspace and cannot be replayed.Credential for one acknowledgement
Role acknowledgement
The boot-time POST that consumes the role nonce, marks the machine active, stamps its check-in time, and returns staged role configuration.Short form: role ack
Role config
An operator-staged JSON object persisted by the control plane and delivered verbatim in the next role-ack response. For a frame it holds source and token.Courier payload
Frame role
The aarch64 RAM role that starts the supervised image renderer and writes composed images to available sinks.Role, not photo record
Frame source
The trusted photo service that authenticates the device bearer token and returns the curated manifest plus protected image bytes.Source stays authoritative
Manifest
JSON containing an images array of names, optional URLs, and optional SHA-256 digests. It is the complete current set known to the frame.Machine-readable collection view
Source token
A long-lived bearer credential scoped by the photo service to read one curated collection and its assets. It is unrelated to the role nonce.Never log or commit
Sink
An independent output adapter receiving a composed image: HDMI framebuffer, preview PNG, or an optional e-ink panel.Source → compose → sink
Beacon
A one-shot report that proves the boot crossed a named runlevel milestone. It answers “did we get this far?”Milestone signal
Heartbeat
A periodic report of current boot state, uptime, service progress, temperature, and board power health. It answers “what is it doing now?”Current-state signal
Watchdog
An out-of-band recovery policy that may power-cycle a truly unreachable node with thresholds, drain time, backoff, and a hard cap. The current age-based probe is not frame-safe.Recovery, not liveness truth
